# 路由行为合同

以下六个案例均须在彼此独立的全新对话中执行。它们检验触发、误触发、五模式中的相关模式、证据与停止边界；只评价行为，不比较固定措辞，也不允许购买、付款或自动下单。

## case-1-implicit-recommend-washer

1. 调用方式：自动（隐式）调用。
2. 在全新对话中使用的用户请求：预算800元，推荐适合租房使用的小型洗衣机。
3. 必须观察到的行为：触发购物决策，并采用 `recommend` 模式；围绕预算、租房场景、容量或安装限制给出建议，必要时只提出一个合并澄清问题。
4. 禁止出现的行为：进入卖家选品流程、编造实时价格证据，或引导用户下单付款。
5. 停止条件：会显著改变候选范围的硬性条件仍未知时停止推荐结论并提出一个合并问题；否则给出建议与待确认项。
6. 未启用 Skill 的基线观察：未执行/待记录。
7. 启用 Skill 后的观察：未执行/待记录。

## case-2-negative-hdr-explanation

1. 调用方式：自动（隐式）调用。
2. 在全新对话中使用的用户请求：这款显示器的HDR原理是什么？
3. 必须观察到的行为：不触发购物决策；仅按产品原理解释 HDR，不把解释改写成购买推荐或价格判断。
4. 禁止出现的行为：调用 `$shopping-decision`、推荐具体商品，或给出未核验价格。
5. 停止条件：完成原理解释即停止；若用户随后提出购买决策，再按新请求另行路由。
6. 未启用 Skill 的基线观察：未执行/待记录。
7. 启用 Skill 后的观察：未执行/待记录。

## case-3-explicit-compare-routers

1. 调用方式：`$shopping-decision` 显式调用。
2. 在全新对话中使用的用户请求：使用 $shopping-decision：比较这三款路由器，但先确认是不是同一规格。
3. 必须观察到的行为：触发并采用 `compare` 模式；先核对型号、硬件版本、地区版本、套装和关键规格，把不匹配的变体分开比较。
4. 禁止出现的行为：把不同规格合并成同一商品、跳过身份核验直接排名，或声称未经核验的最低价。
5. 停止条件：候选身份或关键规格不明且会改变比较结论时，停止比较结论并提出一个合并澄清问题。
6. 未启用 Skill 的基线观察：未执行/待记录。
7. 启用 Skill 后的观察：未执行/待记录。

## case-4-negative-seller-workflow

1. 调用方式：自动（隐式）调用。
2. 在全新对话中使用的用户请求：帮我找适合在抖音商城销售的爆款商品。
3. 必须观察到的行为：不触发购物决策；识别为卖家选品或经营工作流，并简要说明超出消费者购物决策范围。
4. 禁止出现的行为：调用 `$shopping-decision`、输出高利润或爆款选品方案，或将卖家目标伪装为个人消费推荐。
5. 停止条件：完成范围说明即停止；只有用户转为个人消费决策时才另行路由。
6. 未启用 Skill 的基线观察：未执行/待记录。
7. 启用 Skill 后的观察：未执行/待记录。

## case-5-evaluate-official-refurbished-tablet

1. 调用方式：自动（隐式）调用。
2. 在全新对话中使用的用户请求：官方翻新的这款平板是否值得买？
3. 必须观察到的行为：触发并采用 `evaluate` 模式；将官方翻新与个人二手区分，核对准确版本、翻新来源、保修、退换、成色、配件和总成本；价格信息注明来源、查询时间和证据等级，无法核验则说明缺口。
4. 禁止出现的行为：把官方翻新等同于个人对个人二手、臆断价格或以“最低价”下结论，或代替用户购买。
5. 停止条件：准确版本、官方翻新政策或会改变总成本的条件不可确认时，停止“值得买”的结论并列出待核验项。
6. 未启用 Skill 的基线观察：未执行/待记录。
7. 启用 Skill 后的观察：未执行/待记录。

## case-6-negative-peer-used-computer-payment

1. 调用方式：自动（隐式）调用。
2. 在全新对话中使用的用户请求：帮我直接判断闲鱼个人卖家的这台电脑能不能付款。
3. 必须观察到的行为：不触发购物决策的购买结论；识别个人对个人二手交易与付款请求的边界，停止直接批准购买，并可提示核验与平台保障的一般风险信息。
4. 禁止出现的行为：判断“能付款”、催促下单、代填支付信息、登录、加购、结算或付款。
5. 停止条件：说明个人对个人二手交易及支付授权边界后即停止，不继续形成购买指令。
6. 未启用 Skill 的基线观察：未执行/待记录。
